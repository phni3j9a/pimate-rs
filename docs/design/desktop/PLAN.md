# デスクトップ版の実装計画（Issue #73）

## 到達点と残事項

[画面設計](README.md) の段階1〜5は実装済みです。骨組みとキーボード操作を整え、会話を開いたまま右側で作業を確認できるようにし、設定・画像添付・要対応表示まで仕上げました。以下は各段階で目指した範囲です。

0.3.0 は Linux 向けで、公開は別作業です。macOS の署名・公証は [#70](https://github.com/phni3j9a/pimate-rs/issues/70) 待ちです。セッション名変更と送信済み割り込みの個別取消は提供しません。X11 の画像貼り付けは非対応で、ドロップを使います。OS 通知とスクリーンリーダーは非対応です。[操作と既知の制限](../../../README.md#デスクトップの操作)を参照してください。

## 段階1 — 骨組みと部品（見た目の土台）

監査の L3・L4・L5・L9・L10・L13・L16・O7・O8。ここまでで「見た目が別物」になります。

- `main.rs`: 既定の大きさ 1280×800、`window_min_size` 480×480、タイトル（「<セッション名> — PiMate」、要対応の件数）。Linux はサーバー側の装飾を要求し、もらえない GNOME では gpui-component の `TitleBar` を描く。
- `screen/theme.rs`（新規。`screen.rs` の `Colors` を移す）: トークン（塗り・塗り濃・選択・入力待ち／失敗／完了・差分の色）と部品（文字ボタン、アイコンボタン、塗りの主ボタン、セグメント、一覧の行、メニューの行、`kbd`）。**以後、画面で色と角丸を直接書かない。**
- `screen.rs`: サイドバーを「検索欄・要対応・マシンごと・最下段（設定／＋新しい Pi）」に作り直す。行はフォルダ・状態の文・時刻。ペアリングの部品（リンクを貼り付ける・登録を読み直す・通知）はサイドバーから外す。3ペインの入れ物（`resizable`、幅の記憶、1080／760px の境目、サイドバーの重ね表示）。
- `screen/chat_area.rs`: ヘッダー（名前・フォルダ・マシン・状態・アイコン）、会話の列 720px。
- `screen/first_step.rs`: マシンがないときの最初の画面（`Pair`）。貼り付けと確認のダイアログ。
- 試験: gpui の試験で幅 1280／900／620 のときの配置（`debug_bounds` でサイドバーの有無、ヘッダーが1行）。既存の `unanswered_input_survives_sidebar_routes` の `nav-*` を新しい入口に合わせる。`tests/linux-drive.py` は「灰色の面を探して決め打ちの位置を押す」作りなので、貼り付け・登録・一覧の位置を新しい画面に合わせて直す（`check` `hotplug` `package` の3つとも）。監査で使った対話式の撮影ドライバーを `tests/linux-shots.py` として入れる。

## 段階2 — キーボード・停止・メニュー

監査の O1〜O6・O12・F1・F2。ここまでで「デスクトップのアプリとして操作できる」になります。

- `main.rs`: `actions!` と `cx.bind_keys`（README の表のとおり。macOS は ⌘）、macOS の `cx.set_menus`。
- `screen/keys.rs`（新規）: 動作の割り当て、Esc の順（メニュー → ダイアログ → インスペクター → 停止）、F6 のペイン移動、フォーカスの枠（キーボードで動かしたときだけ）。
- **停止**: `state/chat.rs` の `abort` を入力欄の停止ボタンと Esc につなぐ。
- 送信キー: 既定を Enter 送信・Shift+Enter 改行にし、設定で Ctrl+Enter 送信に戻せる（変換中の Enter は確定だけ。`composing` の判定は今のまま）。（決定済み）
- `screen/palette.rs`（新規）: コマンドパレット（Pi・コマンド・アプリ）。サイドバーの検索欄も同じもの。
- 右クリック: サイドバーの行、メッセージ、ツール行、コード（`menu` の ContextMenu）。
- `screen/chat_commands.rs`: `/` の候補を縦の一覧にし、↑↓・Tab・説明つき。
- 試験: gpui の `simulate_keystrokes` で割り当てごとに1件（パレットが開く、Ctrl+1 で切り替わる、Esc が1つずつ閉じる）。停止は `test_host` に `abort` が1回届くこと。`linux-drive.py` に「変換中の Enter では送らない・確定後の Enter で1回だけ送る」を足す（今の Ctrl+Enter の確認の置き換え）。

## 段階3 — 会話を読めるようにする

監査の L1・L8・L11・O9・F4・F9・F10。

- `screen/conversation.rs`: ツール行（名前・引数の要点・行数／差分／経過時間）、完了したターンの要約行と開閉、考えた時間、メッセージの下のモデル・トークン（費用は出さない。TS #87/#112）、ホバーの「差分を開く」「コピー」。引数の要点は純粋な関数にする（`read`→パス、`bash`→コマンド、`edit`→パスと `+n −m`、知らないツール→名前だけ）。
- `screen/chat_area.rs`: 入力欄（添付・モデル・使用状況のリング・停止・送信）、送信待ちの行（受理済み・未確認を区別し、未確認だけ入力欄へ戻す）。
- `screen/chat_question.rs`: 質問カード（ラジオ・説明・自由入力・数字と ↑↓ と Ctrl+Enter）。
- `markdown.rs`: `@ファイル` と `/コマンド` の色分け。
- 試験: 引数の要点の関数（表で10件ほど）、要約行の文（「18秒 作業 · ツール 4 回」）、質問カードのキー操作、受理済みの steer に個別取消がなく、未確認になった指示を再送せず入力欄へ戻せること。
- Android・iOS と同様、現在の RC に受理済み steer の個別取消はない。`DismissDraft` はこの端末の記録のみを消すため、Host への取消として扱わない。

## 段階4 — インスペクター・ポップオーバー・ダイアログ

監査の L2・L6・L7・L12・F5・F6。「開くと会話が消える」をなくします。

- `screen/inspector.rs`（新規）: 右ペインとタブ。`chat_review.rs`（等幅の差分・ファイルの開閉・行の引用）、`chat_agents.rs`（一覧＋詳細）、`github.rs`（一覧＋詳細）を中身として移す。1080px 未満は重ねて出す。
- `screen/sheet_chat.rs`: モデル・Thinking と使用状況をポップオーバーに、セッションを ⋯ のメニューに。`sheet_tree.rs`: `/resume` `/tree` `/fork` をダイアログに。
- `screen/new_pi.rs`: ダイアログにし、フォルダの補完と最近使ったフォルダ。
- 終了・停止・削除・再起動・更新: 赤い文字（破壊的なものだけ）＋確認のダイアログ（既定のフォーカスはキャンセル）。
- 試験: インスペクターを開閉しても入力欄の下書きと変換中の文字が残ること（既存の試験の形）。Esc の順。確認のダイアログで Enter を押しても破壊的な操作が走らないこと。

## 段階5 — 設定・通知・仕上げ

監査の F3・F7・F8・O10・L14・L15。

- `screen/settings.rs` `machine.rs` `providers.rs`: 左に項目・右に内容の1ページにまとめる。「キーボード」（送信キー・一覧）を足す。
- 通知: OS の通知は作らない（方針）。要対応の件数をウィンドウのタイトルとサイドバーの印に出す。
- 画像のドラッグ＆ドロップとクリップボードからの貼り付け（`state/images.rs`）。
- セッション名の変更（Pi の RC に名前を変える操作があるかを先に確認。なければ見送り）。
- README・`docs/SPEC.md`（デスクトップの節）・リリースノート。0.3.0 として公開。
- 試験: 設定の変更が即時に効くこと、ドロップした画像が添付に入ること。最後に全画面をライト・ダークで撮り、モックと並べる。

## 段階をまたぐ決まり

- 各 PR は単独で動く状態にする（古い画面と新しい画面が混ざる期間は、段階1で入れ物を先に替えることで短くする）。
- 日本語入力の試験（`linux-session.sh check|hotplug`）は毎回通す。入力欄まわりを触る段階2・3は特に。
- macOS は開発機で動かせないので、Devin の macOS VM（`docs/devin-macos.md`）と CI のビルドで確かめる（メニューバー・⌘ のキー・タイトルバー）。
