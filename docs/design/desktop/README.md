# PiMate デスクトップ 画面設計

デスクトップ版（GPUI、macOS・Linux）の見た目と操作の基準です。スマホの [画面モック](../README.md) の色・文字・部品の決まり（[トークン](../html/Tokens.html)）と [アイコンキット](../icon-kit/README.md) をそのまま使い、置き場所と操作をデスクトップの作法に合わせ直しています。仕様の正本は [docs/SPEC.md](../../SPEC.md) です。

- なぜ作り直すか: [AUDIT.md](AUDIT.md)（0.2.0 の監査）
- どの順で作るか: [PLAN.md](PLAN.md)
- **状態: 設計の確認待ち。アプリのコードはまだ変えていません。**

## 見方

`html/*.html` をブラウザで開きます（`?theme=dark` でダーク）。ウィンドウは 1280×800、その下の文はモックの注釈で、アプリには出ません。画像は `review-assets` ブランチの [`73/mock/`](https://github.com/phni3j9a/pimate-rs/tree/review-assets/73/mock) にあります（作業ブランチと main には入れません）。作り直すときは `node docs/design/desktop/export.mjs [出力先]`。

モデル名・料金・フォルダ名などの値は例です。ショートカットは Linux の表記で、macOS は Ctrl を ⌘ に読み替えます。

## デスクトップの作法

**並べ方（広いウィンドウを生かす）**

| ウィンドウの幅 | 並べ方 |
|---|---|
| 1080px 以上 | サイドバー（264px、220〜360 に変えられる）＋ 会話 ＋ インスペクター（400px、320〜640。開いているとき） |
| 760〜1079px | サイドバー ＋ 会話。インスペクターは会話の上に重ねる |
| 760px 未満 | 会話だけ。サイドバーはヘッダーのボタンか Ctrl+B で重ねて出す。最小は 480×480 |

会話は幅 720px までの列を中央に置きます。ペインの幅と開閉は覚えます。

**何をどこに出すか（スマホのシートの行き先）**

| 種類 | 使うもの |
|---|---|
| Pi からの質問・PC で操作が必要・再接続 | 会話の中（モーダルにしない） |
| 会話と見比べるもの: 変更・サブエージェント・GitHub | 右のインスペクター（モーダルにしない） |
| その場で選んですぐ閉じるもの: モデル・Thinking、使用状況、送信のタイミング、セッションのメニュー、右クリック | ポップオーバー／メニュー（押した場所のそばに出す） |
| 入力して確定するもの・選んで切り替えるもの・確認: 新しい Pi、ペアリングの確認、`/resume` `/tree` `/fork`、終了・削除・停止・再起動・更新の確認、画像の拡大、パレット、ショートカット一覧 | ダイアログ（中央。背景を薄く暗くする） |
| 設定（マシン詳細を含む） | メインを置き換えるページ（サイドバーは残す） |

**マウス**: ホバーは一段濃い面、選択は選択色。ツール行やメッセージの操作はホバーで出します。右クリックは、サイドバーの行・メッセージ・ツール行・コードとパス・画像・入力欄で効きます。ペインの境目はドラッグできます。ツールチップはアイコンだけのボタンと、省略された文字にだけ出します。

**キーボード**: すべての操作をキーボードだけでできるようにします。割り当ては `Shortcuts` の表が正です。フォーカスはアクセント色の 2px の枠で、キーボードで動かしたときだけ出します。Esc は「メニュー → ダイアログ → インスペクター → 停止」の順に1つずつ効きます。

**部品（スマホと同じ決まり）**: 塗りの主ボタン（カプセル型）は1画面に1つ（会話では送信、ダイアログでは確定）。サイドバーの「＋ 新しい Pi」だけは常に出る例外です。ほかは文字かアイコン。終了・削除・停止・取り消しは赤い文字で、押すと確認を出します。区切りは面の濃淡と余白で、影は浮く面（メニュー・ポップオーバー・ダイアログ）にだけ使います。

**GPUI で作れる範囲**: ぼかし・グラデーション・動きのある効果は使っていません。面・角丸・1px の線・影・文字・小さなアイコンだけです。メニュー・ポップオーバー・ダイアログ・幅を変えられるペイン・タイトルバーは、導入済みの gpui-component 0.5.1 にあります。

## 決めてほしいこと

設計のうち、利用者の好みや運用で決まるものです。モックは「案」の側で描いています。

1. **送信キー** — 案: Enter 送信・Shift+Enter 改行（変換中の Enter は確定だけ）。設定で今の「Ctrl+Enter 送信・Enter 改行」に戻せる。／別案: 今のまま（誤送信は起きないが、毎回2つのキーが要る）。
2. **会話と見比べるものの出し方** — 案: 右のインスペクター1つにタブ3つ（変更／サブエージェント／GitHub）。同時に見られるのは1つ。／別案: GitHub はインスペクターに入れず、設定と同じ「ページ」にする（一覧が広く見えるが、会話は隠れる）。
3. **通知** — 案: 段階5で「オフ／要対応／すべて」と OS の通知を入れる。Linux は D-Bus の通知、macOS は署名済みアプリの通知。／別案: まずウィンドウのタイトルとサイドバーの印だけにして、OS の通知は 0.3.0 のあとに回す（macOS は開発機で確かめられないため）。
4. **Linux のタイトルバー** — 案: OS のものを使い、もらえない GNOME ではアプリが描く（閉じる・最小化・最大化つき）。／別案: どの環境でもアプリが描き、検索欄やサイドバーのボタンをタイトルバーに入れて縦を 32px 節約する（作る量と環境ごとの確認が増える）。
